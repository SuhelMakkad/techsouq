6. FICTIONAL WORKED EXAMPLE
Assumptions: custom enquiry website; private interface package; test database;
email sandbox; permission to rehearse; a text-only confirmation change.

Initial checks:
1. Core account administration: PASS (source hosting, web hosting, test data, and email; private package authorization checked separately).
2. Released source available: PASS.
3. Test configuration documented: PASS.
4. Test database isolated: PASS.
5. Clean build can fetch private package: FAIL (supplier access dependency).
6. Form notification reaches test inbox: NOT CHECKED.

4 passed + 1 failed + 1 not checked = 6 checks.
The build failure blocks release; this is not a readiness percentage.

Remedy: arrange agreed package authorization, check the licence arrangement, and document access. Incoming developer repeats the clean build, runs checks, and deploys to the isolated test site. A synthetic enquiry creates the test record and reaches the sandbox inbox. Reverse the text change and verify it.

Checks 5 and 6 now pass with evidence. The first four remain valid for the unchanged test setup: 6 passed, 0 failed, 0 not checked within rehearsal scope. Production access, configuration, and message delivery remain separate checks. These are invented test conditions, not client results or benchmarks.
